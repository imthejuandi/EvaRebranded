# EVA Preview Review

Work from the existing EVA rebrand and approved Codex preview. Check the current branch, route, existing implementation, project review workflow, and latest owner direction. Don't rebuild the site or use an older standalone mockup as the brand source. Preserve approved assets, components, and unrelated work. Treat a proposal, a private preview, and release as distinct scopes.

## Write the implementation brief

State the customer question or action, why it matters, exact change and non-goals, approved reference and rejected options, confirmed product facts, and observable pass/fail criteria. Put the newest decision above earlier feedback. Keep one job per section. Name what should stay and where the user should land after each action.

## Assign and verify

Choose specialists proportional to the change. Wellness marketing owns message and copy; use a separate primary-evidence or qualified medical review for new health claims. Check explanation with a first-time reader lens and check idiomatic ES/EN. Frontend Design and existing EVA brand guidance own layout and interaction; give Impeccable a separate typography, spacing, and reflow pass when available. Use the exact runner, eva® wordmark and project assets. Use references such as SAVEE for proportion and restraint, not to replace the brand; generate new media only if needed and within scope.

Where available, Astra is a good fit for difficult visual work or independent judgment; Sol for a tightly scoped build or reproducible checks. Respect any explicit model assignment (e.g., Astra for design only) and do not let design rewrite approved copy. Keep the final judge independent of the author on material changes. Name meaningful substitutions or missing reviews instead of inventing model assignments. A distinct rubric is useful; reviewer count alone is not evidence.

Render the exact candidate. Test the affected journey in ES and EN, on desktop and narrow mobile (320/390 px where relevant), with actual interactions, keyboard, and motion preferences as applicable. Ask the judge to report pass/block by relevant criterion with screenshot or reproducible evidence and the smallest correction. Fix blockers, rerender, and rerun affected checks and regressions. Stop when criteria pass or a genuine unresolved product decision, permission, or verification limit remains. No private or production health data in preview checks. Report exact preview, changes, checks, limits, and any real decision needed; a pass is not release approval.

Read [the decision ledger](references/decision-ledger.md) when working on the landing page or when a past correction is relevant. After each material iteration, record the latest owner decision, rejected alternative and why, and the regression it implies. Record reviewer suggestions and unverified assumptions as such. Update the skill itself only when repeated use reveals a transferable workflow improvement, not for every one-off preference.
